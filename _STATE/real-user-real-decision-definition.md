# Real User / Real Decision — target definition (v0.1)

acquisition, NOT validated ICP.** Every claim below is testable, not known. Run it through its own

## 1. A real user is a STATE, not a segment
Per `icp-is-a-state-not-a-segment`: a real user is not a title / industry / company size. It is a
person currently **in the decision-state the compass serves**:
- at a genuine **fork** (not a settled question with a preferred answer already),
- under **pressure** (the decision won't wait),
- in **fog** (they can't yet see which line is uphill),
- with real **skin in the game** (the outcome costs *them*, personally).

You don't acquire a state; you find people likely to be in it and catch them *at the moment*
(caught-breath). "Sign up, here's a tool" gets accounts, not real users.

## 2. What makes a decision "real" (vs a test / dogfood)
Calibrated by the product's own example questions (Series A now vs extend runway; exit partnership
vs restructure):
- **High personal stakes** (career, money, relationship, company direction).
- **Genuine uncertainty** — they don't already know the answer; they want the terrain read, not a rubber stamp.
- **A live horizon** — a real deadline/window, not hypothetical.
- **NOT**: a demo question, a test of the tool, a decision already made, or a low-stakes triviality.
- **The tell:** the author would still be turning this over at 2am whether or not ARCS existed.

## 3. Acquisition proxies — where the state clusters (HYPOTHESIS, inferred not measured)
You can't target a state directly, so target populations that hit it often *and* acutely. Keep the
**first wedge narrow** — one population, one decision-type — so the quarter is measurable:
- Founders mid-raise / at a pivot fork (the example questions skew here).
- Operators/execs at one-way-door calls (exit, restructure, key hire, big bet).
- (`arcs-coaching-exoskeleton-gtm-wedge` is the nearest banked wedge thesis.)
Reach-flag: inferred from the examples + a memory, NOT from real users. The first real users correct this.

## 4. Frequency / cadence — UNKNOWN, must be measured not assumed
Episodic (a few big forks a year) or recurring (weekly small forks)? This decides whether ARCS is a
retention product or an episodic one, and it changes what "a real user" even means (one big decision
vs a habit). n~4 can't answer it — the acquisition quarter must *measure* it.

## 5. THE MEASURABLE ANTI-DOGFOODING TEST (the crux — this is what §makes acquisition countable)
So the quarter ends with a real number, not "30 more receipts that are still effectively dogfooding."
A receipt counts as **REAL** only if ALL hold:
- **(a)** authored by a **non-founder account** (not zach.harris@gmail.com, not a test/anon self-session),
- **(b)** on a decision with the author's **own genuine stakes** (§2, not a demo/test question),
- **(c)** the author **returns to log an outcome** — an unclosed receipt from a stranger is a signup, not a validated real use.

**Quarter-end scorecard:** count receipts satisfying (a)+(b)+(c), and the number of **distinct
non-founder users** behind them, and how many of those users logged **>1**. Pick the real target
(the compass tributary floated ~20 users — choose deliberately). If the count is ~0 despite
acquisition effort → you acquired signups, not real users → the gap is state-targeting or product-fit,
NOT distribution volume.

## 6. Its own doubt-the-premise gate (run BEFORE spending the quarter)
The single confound that would invalidate "we got real users": **acquiring people who each make one
test-drive decision and churn = dogfooding at the population level** (many strangers, no real repeated
use). So success can't be "N signups" or even "N receipts" — it must be the (a)+(b)+(c) count above,
across M distinct users, ideally with some M making >1. **Decompose the denominator before declaring
success** — the exact lesson from the 247 (a confirmed count says nothing until you ask whose).

## 7. Generalization — this is one instance of a domain-agnostic REALNESS GATE
This definition is a special case of the gate this session kept running: the counterfeit/reach test
that separates a real instance from a fabricated/test one, across ANY entity. Same three axes every
time — **animacy** (is anyone/anything genuinely home), **provenance** (not self-generated),
**execution** (closes against reality). Instances this session: SAGE's `somatic` (fabricated signal),
the meta-reversals (generated, not real insight), the 247 (dogfood, not real users), the take-home
caller (not a real person). "Real user / real decision" is that gate for the human-decision domain.
It applies equally to:

- **Real OUTCOME** (immediately relevant — and it moves the number). An outcome is real only if it's
  an externally-observed consequence with provenance, not self-asserted. Apply the gate to 2/247:
  both logged outcomes sit on the **founder's own receipts, closed by the founder** — self-grading,
  which §5.1 ("a receipt cannot be closed by the session that created it") exists to exclude. They're
  not fake (a real what-happened was logged) but they're **self-assessed, not externally validated** —
  exactly the "self-graded until outcomes accumulate" admission already on `status.html`. So by the
  realness gate the **externally-validated outcome count is ~0/247, not 2.** The razor, one level deeper.
- **Real AGENT-user** (hypothetical — no instances yet). An agent is a real user iff it decides through
  ARCS for a real stakeholder, with real downstream stakes, and the loop closes against a real result.
  An agent running synthetic/test decisions is dogfooding — identical to a human demo. The
  (a) non-self / (b) real-stakes / (c) closes-loop test is substrate-agnostic.

**Reach:** the gate-as-pattern is accreted (≥4 domains this session). The agent instantiation is
generated/hypothetical. The ~0-real-outcomes claim is checkable and follows from §5.1 + both outcomes
sitting on the founder's own self-authored receipts.

## 8. Why capture is behaviorally hard — the null's likely content (YELLOW hypothesis)
The [meta] tributary: 2/247 non-closing is not only a build gap — the non-closing is a *signal read
as null*. Likely content (unverified, per `false-null-requires-provenance-exhaustion`: can't be
stamped without asking the non-closers, which is itself the capture problem):
- **Ex-ante: mis-weighted stakes.** Underweight → decision feels trivial → not worth tracking. Overweight
  → feels overwhelming / outcome too painful → avoidance. Both mis-weightings route to non-closing.
- **Ex-post: forget the fitting.** Even with right stakes, nobody returns to fit outcome to prediction —
  moment passed, no trigger, effort. Measured once, never fitted.
- **Self-reinforcing loop (why the fitting is the keel):** mis-weight → don't fit → never learn you
  mis-weighted → keep mis-weighting. The fitting is the one act that breaks it, which is precisely why
  capture-rate is the keel: the loop that most needs closing is the one people are built to leave open.
- **Design consequence:** the capture mechanism fights avoidance+forgetting — must trigger the fitting,
  keep it *surgical* low-friction (matched/regret binary, not deep reconciliation that triggers the
  overweight-avoidance), and reframe the calibration-error-revelation as the value, not the indictment.

Reach: GREEN that absence-of-outcome is a signal not a null; YELLOW that the signal's content is
"mis-weight + forget" — plausible, un-verified, testable only by the capture it explains the absence of.
