# JTBD orphanage audit

The JTBD gate held 352 orphan tools and 151 orphan jobs on 2026-11-05. This pass gave every held id one verdict, applied the safe FAMILY edges, and left the rest as proposals. The baseline now holds 336 orphan tools (down 16) and 151 orphan jobs; `python3 scripts/universe_jtbd_adapter.py --check` passes.

## What changed in this PR

1. **Edge builder fix (14 tools).** The cite rule only counted a shell run when the line began with the interpreter, and it skipped any shell line that held a message word (`echo`, `raise`). So `echo "$f" | xargs -0 python3 scripts/x.py` in the pre-commit hook, `"$_d/scripts/x.sh"` and `python3 "$CLAUDE_PROJECT_DIR/scripts/x.py"` in the session-start hook, and `python3 scripts/x.py || fail "...raise the token..."` in nftt-gates.sh gave no edge. Now, in shell, a match counts when the line starts with a run or the match follows `&&`, `||`, `;`, `|`, `$(`, `then` or `do` (xargs flags included), and the match sits outside a quoted literal. Eight new fixtures cover the good and bad cases. All 31 new cite edges were read by hand against their source lines: each is a real run.
2. **Two judgment edges** in `runtime/specs/jtbd-graph-inferred-edges.json`: `tools/cold-recon` serves `agent-receipts-audit-offer` (the row productizes cold-recon itself), and `taxonomy-conflict-ledger-and-atlas-edges` needs `memory_catalog_emit.py` (its slice 2 builds from that adapter). Both rows named the tool in a form the builder cannot resolve.
3. One triage hold cleared (`adr_dewy_watch.py`, now attached through the session-start hook).

Rejected on reading: `sbom-payload-scan` for `rfp-ship-public-leak-gate` (it scans incoming untrusted repos, not outbound leaks), `faq-eval` for `hud-cold-read-acceptance` (it scores README FAQ coverage, not a HUD cold read), `prl-page-factory` for `prl-phase-path-close` (a sales close, not a page build), and every `castellum.py` hit (castellum found those pressure rows; it does not do them).

## Decisions for Zach

1. **Rule change, the biggest lever (251 ids).** Exempt surfaces (pages) from ORPHAN-TOOL and terminal rows from ORPHAN-JOB in `scripts/jtbd_graph_gates.py`, by an amendment to the pre-registration. That clears all 210 page atoms (149 outputs plus the 61 counterpart pages, whose alias fate stays yours) and the 41 closed rows without hand edges. Grug's read on the plan was the same: one owned rule edit beats hundreds of verdicts. Not applied here, because the rules are pre-registered and an amendment is yours.
2. **Standing tools (40 ids) go to `jtbd-standing-tools`.** Two mechanical gaps feed it: CI workflows are not catalog atoms, and calls by `$(dirname "$0")/x`, JS `execFileSync` argv and slash-command names are not read. The row already lists these as candidate mechanisms; this audit only adds the member list.
3. **CUT (49 ids):** the May 2026 kernel scripts, the unbuilt GIGI operator layer, finished experiments, and operator atoms that are UNBUILT or have no consumer. Archive moves trip `archive_move_gate.py` until citers are re-pointed (arcs_core.py is cited by ADR-023).
4. **Counterpart microsites (61 ids):** keep or retire each alias per engagement.
5. **On-demand instruments (36 ids):** wire each into a recurring row or archive it (the global "one-shot ingest decays" rule).
6. **Two jobs are a standard feature:** `jsonl-ledgers-merge-union` is the built-in git union merge driver (no `.gitattributes` exists yet), and `prisma-8-upgrade-plan` is the Prisma upgrade guide. The wrapper scripts I first marked STANDARD were checked by the platform-standards-auditor: five add a real guard (docs-only push, merge without stash, macOS-safe timeout, subdomain alias check, clean-URL static serve), so they moved to standing tools or instruments; only the one-time Prisma baseline is CUT.
7. **Defect found in passing:** `scripts/deploy-prod.sh` hardcodes `MAIN_WORKTREE=.../frosty-kepler-b69f51`, which no longer exists, so the script cannot run as written.
