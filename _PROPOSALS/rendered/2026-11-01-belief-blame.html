Belief blame: blame the assumption, not the author

git blame says who last touched a line. Belief blame says which assumption the line encodes, the commit it entered in, which evidence later shifted it, and whether the line is still current or is now a known blindspot. Point it at any line of a process file (AGENTS.md, _PATTERNS, _DECISIONS, .claude/rules, script headers) or any backlog depends_on edge.

§ The short version
The idea (Zach, 2026-11-01)"what if our blame was process assumptions or dependancies or blindspots that changed over time based on observed new evidence that shifted our beliefs". The thing blamed is a belief and the evidence that moved it, not a person.
What the trace foundA hand trace of the first real line (AGENTS.md gotcha 17), done the way the tool would, found a live blindspot: the belief "branch protection cannot enforce this on the free plan, so detection, not prevention" was rewritten in AGENTS.md on 2026-10-06 (1c798b7b), but the same sentence still stands in scripts/squash_merge_detector.py line 7. It also found a relapse: falsification row F26 (2026-07-24, a merge went through on a red check) and the safe_merge.sh Tuition (2026-10-20, a merge went through on a PENDING check) are the same belief failing twice, and the later record does not cite the earlier one.
Why git blame alone is wrong heregit blame -w -C on gotcha 17 credits 51ddf069 (2026-10-20, safe_merge.sh). The never-squash belief entered on 2026-09-28 (0df06046). Blame gives the last rewording; belief blame must walk the line's history (git log -L, then git log -S on the quoted phrase) to the first commit that stated the assumption.
What it addsOne optional field, anchors, on falsification-ledger and assumptions rows (path plus a quoted phrase, never a line number). One read-only script that joins line to commit to assumption to evidence and prints a verdict. No new store, no model calls. Everything else already exists.
§ Decisions waiting on you

D1Add an optional anchors field to _STATE/falsification-ledger.jsonl and _STATE/assumptions.jsonl rows: a list of {path, phrase} naming the lines that encode the belief?

Recommended: Yes. It is the one missing join key. Today F-rows cite ADRs, specs and runs, and asm rows cite depends_on_it paths, but nothing points at a line, so no tool can go from a line to its belief.

A phrase survives line moves and rewording of nearby text; a line number goes stale on the next edit above it. Text search alone cannot tell two uses of the same words apart.

D2Report a belief's exit on both axes: truth (falsified, or still held) and liveness (moot, superseded), and for a falsified belief say whether the world changed or the old belief was wrong all along?

Recommended: Yes, as fields in the verdict, not prose. Gotcha 17's 2026-10-06 shift was revealed incompleteness: the merge-method setting existed on every plan the whole time; the belief that enforcement was impossible was false when written.

Memories claim-exit-lattice and defeasible-warrant: a falsified claim you correct, a moot claim you vacate and mark; calling a miss a change hides the miss.

D3Fix the blindspot the trace found (scripts/squash_merge_detector.py line 7 still says branch protection cannot enforce the policy) as its own one-line docs PR, citing commit 1c798b7b?

Recommended: Yes, separately and after this proposal, so the fix is the first receipt that cites a belief-blame finding.

The detector still works; only its stated reason is stale. A stale reason misleads the next reader into thinking the detector is the only guard.

D4Should a Tuition note in a script header that repeats a falsified belief be required to cite its F-row (and, when none exists, mint one)?

Recommended: Yes, as a warning first (control K2), then a gate after 30 days if the false-positive rate is low.

F26 and the safe_merge.sh Tuition are the same failure three months apart. The ledger had the lesson; the fix did not carry it, so the class came back.

D5Where does belief blame render first?

Recommended: CLI only (a read-only script with --self-test), then feed the WORLD.md HUD Time layer, which already promises belief change scrubbed by date with a falsified belief as a gold seam.

The HUD needs the join to exist before it can draw it. A visual that cannot go flat on empty data is decoration.

§ Heuristics: for you, and for me
For you (human)
  • When evidence changes your mind about a process rule, say which file states the old belief; the harness rewrites every sibling, not only the one in front of it.
  • Ask "did the world change, or were we wrong all along?" A miss called a change is a miss repeated.
  • A verdict of UNREGISTERED is not a defect; it is a belief nobody wrote a test for. Register it only if being wrong would cost something.
For the agent (machine)
  • Never report the git blame commit as when a belief entered; walk git log -L and git log -S on the anchor phrase.
  • Never edit a decided ledger row to record a shift; append a new row that points back (supersedes).
  • When you rewrite a process line because of new evidence, grep for the old phrase across the repo in the same change and cite the evidence id in the commit.
  • Belief blame is read-only. It prints verdicts; fixes go through the normal PR, merge and receipt path.

§ Verdicts

Truth and liveness are separate axes (D2). Every verdict prints the commit or row id that decided it.

VerdictMeaningFix
CURRENTNo evidence row shifted it, or every shift was a hold.none
SHIFTED-PROPAGATEDEvidence shifted it and every anchored line now states the new belief.none; the gold seam is drawn
SHIFTED-STALE-SIBLINGEvidence shifted it and one line was rewritten, but another anchored line still states the old belief.rewrite the sibling, cite the shift commit
RELAPSEDA falsified belief failed again later and the later record does not cite the earlier row.link the records; ask whether the fix was the wrong layer
MOOTThe question retired (the tool or rule was removed or superseded) rather than being answered false.vacate and mark, do not correct
UNREGISTEREDThe line encodes a belief with no assumptions or F-row anchored to it.register an asm row with a test that would decide it

§ Proposed controls and how we will know each works

Each control is a guess until its test runs. A test has a known-bad case that must fail and a known-good case that must pass.

K1Stale sibling proposed

When an evidence row or commit rewrote one anchored line, every other line anchored to the same belief must no longer contain the old phrase.

Must fail
Fixture: two files anchored to belief B, one rewritten at 1c798b7b, the other still containing "Branch protection cannot enforce" (a copy of scripts/squash_merge_detector.py at ce13ec16). Must print SHIFTED-STALE-SIBLING with both paths and 1c798b7b.
Must pass
The same fixture with the detector line rewritten prints SHIFTED-PROPAGATED.

Test status: fixtures to be written first in the script's --self-test (temp git repo, two commits) · line: known-bad flagged, known-good silent

K2Relapse without citation proposed

A Tuition note or kintsugi seam that matches a FALSIFIED F-row's claim, dated after it, must cite that F-row.

Must fail
Fixture: an F-row like F26 (2026-07-24, merge on red check) and a script header Tuition dated 2026-10-20 describing a merge on a PENDING check with no F-id. Must print RELAPSED naming both.
Must pass
The same Tuition with "(see F26)" prints nothing.

Test status: matching is by anchors first, then by a shared anchor path; no fuzzy text match in the gate, so recall is low by design and false positives near zero · line: known-bad flagged, known-good silent; warn only for 30 days (D4)

K3Entry is not last touch proposed

The reported entry commit is the first commit that stated the anchor phrase, not the git blame commit.

Must fail
Fixture: a temp repo where commit 1 adds a line with the phrase and commit 2 rewords other words on the same line. Reporting commit 2 as entered_in fails.
Must pass
entered_in is commit 1, last_touched_in is commit 2. On the real repo, AGENTS.md gotcha 17 reports entered 0df06046, last touched 51ddf069.

Test status: fixtures to be written first · line: both commits match

§ Glossary
Belief blame
A lookup that answers, for one line or one depends_on edge: which assumption, entered when, shifted by what evidence, current or not.
Anchor
A {path, phrase} pair on a ledger row naming a line that states the belief. A phrase, never a line number, so it survives edits above it.
Stale sibling
A second line that still states a belief after evidence rewrote the first one.
Relapse
A falsified belief that fails again later, recorded without citing the earlier falsification.
Revealed incompleteness
The belief was false when written; new evidence only exposed it. Opposite of a world change, where it was true then and is false now.
Tuition
The incident note at the top of a script header recording what went wrong and what the script now prevents.
Moot
The question retired, so the belief is vacated and marked rather than corrected.
