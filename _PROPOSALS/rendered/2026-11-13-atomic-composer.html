Atomic composer

Drag kit parts into the regions of a page and watch it render, with three rendered options to pick from for each part. Plus a ranked list of which visual tool fits which job.

Why

You judge pages by looking at them. Today a page changes through prose ("make the stats quieter") or by hand edits to a JSON data file. Both lose detail, and both take a full round trip before you see the result.

What

A page where you drag kit parts (atoms, molecules, organisms, templates) into the named regions of a template. Its output is the same JSON data file the tabbed-brief builder already reads, so nothing downstream changes. Each part you drop can open an option board: three rendered variants to click between.

Why now

On 2026-11-13 you picked glass treatments for five Gravity blocks from a three-option widget and asked for that method on all visual work, unless you could drag and drop by atomic layer. The option board ships now and covers the first half. The composer is the second half. Nothing external forces a date.

How

Before (done). scripts/option_board.py renders any block-by-block review as a page, an Artifact, or an inline widget.

During (proposed, about 2 days).

  1. Regions come from the template: for the tabbed brief, the masthead, overview tiles, overview sections and each tab's units.
  2. The palette comes from the kit manifest, grouped by layer. A region takes only the block types the brief schema allows there, so you cannot build a page the builder would refuse.
  3. Parts snap into an ordered list per region. No free positioning, so the output is always valid data.
  4. Export writes the JSON file. The builder's existing apply step takes it, the same path the live editor uses.

After. First use on the next counterpart brief. Kill rule, written now: if after three real pages you still reach for hand-edited JSON or prose first, the composer stops and the option board stays the method.

Three ways to build it

Option A · first, your pick

Dashboard widget

The composer runs inline in chat. One row per page region lists its blocks, with up, down and a part picker that shows three rendered treatments. Send posts one block-sequence line, and the session writes the brief's JSON.

About half a day. Cheapest, but it lives in the chat, and you see lists and thumbnails, not the whole page.

Option B · after the grammar

Component explorer

A page or Artifact: a palette of kit parts grouped by layer, each with three rendered treatments to pick from, and the page's regions as ordered slots you fill by drag or keyboard. The page checks the schema as you drop, and Copy JSON exports what the builder reads.

About 2 days. It tests seed 19's held claim directly and reuses the option board.

Option C · after the grammar

WYSIWYG styling

Extends the live editor on the built brief: insert, move and restyle blocks in place, with a treatment dial per block. It writes back through the builder's apply step.

About 3 days. Highest fidelity, but it changes the shared token-tuner script (825 lines), so it carries the most risk of breaking pages that already use it.

Open: run the composer as a shareable Artifact, or as a local page that writes straight to the repo (proposed default: local, since export has to reach the builder). Two side sessions are testing the composer and the option-board method as public goods; their verdicts may move rank 5.
