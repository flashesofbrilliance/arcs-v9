Kairos backup rule: no window closes in silence

When a timing window is closing and the human trigger has not come, the harness never stays silent. A reversible step may advance on a default declared ahead of time. A one-way door never advances: it escalates, and if the window closes it files a lapse receipt so the miss is a recorded decision, not negligence.

§ The short version
The failureSilence, not inaction. A window missed because nobody noticed is negligence. A window passed up on the record is a decision.
The ruleTwo-way door, known close date, declared undo: advance on the declared default and tell Zach. Anything else: stay at the door, escalate as the window closes, and file a lapse receipt at the close.
Already true"Merge when green" (PR 1919, PR 1920) is the legitimate backup in miniature: Zach released the door ahead of time with a condition, and the harness only watched the condition. Most windows need a release given early, not machinery.
What it addsTwo optional backlog row fields (window_closes, default_if_silent), one gate (default_if_silent is refused on a one-way door), one sort in /loops (closing windows first), and one receipt shape (the lapse receipt). No new store, no model calls.
§ Decisions waiting on you

D1Adopt the rule: an absent trigger never resolves as silence?

Recommended: Yes, as the principle. It costs nothing to state and every later decision hangs on it.

The 2026-10-31 to 11-01 friction (a stale BLOCKED note, PRs merged before the batch reached them) were all silent drift, not wrong actions.

D2Allow default_if_silent on two-way doors only, with the gate refusing it on one-way doors?

Recommended: Yes. A default on a one-way door is autopilot, which the canon deprecates (ARCS-v9-Chapter-Book-Canon.md:472).

Undo is cheaper than a missed window only when undo exists and was declared before the window, not after.

D3Make the lapse receipt a decision_receipt row (mode QUICKMOVE, what_unconfirmed naming the ruling that never came)?

Recommended: Yes, the existing table and form. A lapse is a decision by default and the ledger already holds decisions.

A status_note goes stale (the stale BLOCKED note case); the receipt ledger is append-only and the Accountant already reads it.

D4Should standing conditional releases ("merge when green") be recorded as the preferred kairos backup?

Recommended: Yes: name it in the flight manual as the first thing to ask for when a window has a close date.

It keeps the human trigger and only moves it earlier in time. NOTOMATION holds.

§ Heuristics: for you, and for me
For you (human)
  • When a window has a close date, give the release early and with a condition ("merge when green", "send if they reply by Friday"). That is the backup that keeps the call yours.
  • If you let a window pass on purpose, say so in one line; the harness files the lapse receipt from it.
  • A default is only as safe as its undo. If you cannot name the undo, it is a one-way door.
For the agent (machine)
  • Never advance a one-way door on silence. Escalate, then file the lapse receipt at the close.
  • Run default_if_silent only when door is two-way, rollback is declared, and the close date has passed; quote the default and the rollback in the receipt.
  • A conditional release covers only the act and condition it names; a later act needs a new release.
  • Never call any of this autopilot; the canon deprecates the word. It is NOTOMATION with a declared default.

§ Proposed controls and how we will know each works

Each control is a guess until its test runs. A test has a known-bad case that must fail and a known-good case that must pass.

K1Default refused on a one-way door proposed

The backlog gate fails a row that sets default_if_silent while door is one-way or absent.

Must fail
A row with door one-way and default_if_silent set must fail scripts/backlog_status_check.py --check.
Must pass
A row with door two-way, a rollback and default_if_silent passes.

Test status: fixtures to be written first, in backlog_status_check.py --self-test · line: known-bad fails, known-good passes

K2No close in silence proposed

A row whose window_closes is past, still non-terminal, and has no receipt naming it after that date is flagged.

Must fail
A row with window_closes 2026-10-30, state OPEN, and no receipt must print LAPSED-SILENT.
Must pass
The same row with a lapse receipt dated on or after 2026-10-30 prints nothing.

Test status: needs the receipts export (scripts/universe_receipts_adapter.py --export) · line: known-bad flagged, known-good silent

K3Closing windows sort first proposed

/loops lists rows with a window_closes date before others, nearest first.

Must fail
A row closing tomorrow listed below one with no date fails the open_loops self-test.
Must pass
Nearest close date first.

Test status: fixtures to be written first · line: order matches

§ Glossary
Kairos window
The stretch of time when an act is worth more than it is before or after (ADR-081).
Absent trigger
The human release a row waits for has not come.
Lapse receipt
A decision_receipt row saying a window closed without the act or a ruling, so the miss is on the record.
Conditional release
Zach's go given ahead of time with a condition the harness can check, such as "merge when green".
One-way door
An act that cannot be undone, or whose undo was not declared before it.
