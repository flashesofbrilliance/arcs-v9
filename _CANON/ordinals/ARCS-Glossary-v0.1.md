# ARCS Glossary v0.1

Portable memory shard capturing key operational terms surfaced in the June 24, 2026 late-night ARCS thread. This glossary is a runtime artifact meant to preserve shared language for future sessions; Tier 1 doctrine remains upstream and authoritative.[cite:31][cite:14]

## Purpose

- Preserve high-signal terms from the thread as reusable objects rather than one-off examples.[cite:14][cite:33]
- Support future Claude/ARCS handoffs with a compact vocabulary artifact instead of re-deriving meaning from scratch.[cite:14][cite:33]
- Reduce token burn by converting long-form metaphysical prose into portable operational definitions.[cite:31][cite:33]

## Core terms

### Tokenomics Hall Monitor

- **Type:** runtime governance primitive.[cite:14]
- **Definition:** A small supervisory layer that estimates prompt size, token cost, time-window usage, and likely efficiency before a prompt is sent.[cite:31]
- **Function:** It meters finite Claude or LLM budget and proposes chunking, compression, or deferment when a prompt is too expensive relative to expected altitude.[cite:31][cite:33]
- **Why it matters:** ARCS already treats decisions as inspectable and receipt-worthy; the Hall Monitor extends that logic to prompt economics and session budgeting.[cite:31][cite:14]

### Hemingway Protocol

- **Type:** compression and translation protocol.[cite:33]
- **Definition:** “Write Drunk, Edit Sober” in ARCS form: capture rich prose in ROM, then run a second pass that compresses it into headlines-only morsels for runtime use.[cite:33]
- **Function:** Preserve the generative richness of muse-state writing while producing cheap, high-signal prompt payloads.[cite:33][cite:31]
- **Why it matters:** It separates design-time articulation from runtime delivery, which is aligned with semantic velocity and low cognitive mass.[cite:14][cite:11]

### Muse/Vestal State

- **Type:** creative operator state.[cite:11][cite:32]
- **Definition:** A high-gain receptive mode in which the user experiences themselves as phase-locked with a deeper field truth and able to express latent invariants before fully formalizing them.[cite:11]
- **Function:** Capture metaphysical or resonant insights at high resolution without prematurely collapsing them into rigid rational structure.[cite:11][cite:32]
- **Constraint:** Muse/Vestal state is valid for capture, not for final shipping; outputs should later pass through Hemingway compression or another sober structuring layer.[cite:33][cite:11]

### QSR ARCS

- **Type:** runtime interface pattern.[cite:33]
- **Definition:** A “quick-service restaurant” delivery mode for ARCS in which insights are served as short, typed, friendly morsels rather than long omakase-style expositions.[cite:33]
- **Function:** Improve usability, speed, and token efficiency for Claude and most end users.[cite:33]
- **Contrast:** QSR is the default runtime surface; omakase remains valid for deep Tier 1 or high-stakes work but is not the everyday interface.[cite:33][cite:14]

### Omakase ARCS

- **Type:** long-form design surface.[cite:32]
- **Definition:** The high-context, high-prose, high-metaphysics mode of ARCS expression where invariants are articulated in full depth and nuance.[cite:32][cite:11]
- **Function:** Best used for canon-building, ontology work, and articulating foundational patterns that should not be flattened too early.[cite:32][cite:14]
- **Constraint:** Omakase is expensive at runtime; it should live mainly in ROM or source artifacts, not in every prompt payload.[cite:31][cite:33]

### Kairos Morsel

- **Type:** reusable runtime object.[cite:31][cite:11]
- **Definition:** A small, typed unit of insight containing at minimum an object, a pattern, and a constraint.[cite:11]
- **Function:** Turn peak prose or metaphysical passages into reusable prompt atoms that can be invoked by name.[cite:33]
- **Example shape:** `name`, `when_it_applies`, `what_it_prevents`, `what_it_enables`, `example_use`.[cite:31][cite:33]

### ADR

- **Type:** architecture decision record.[cite:32]
- **Definition:** A durable record of a structural ARCS decision, including the question, chosen direction, rationale, status, and consequences.[cite:32]
- **Function:** Prevent architectural choices from dissolving back into conversational fog; make the chosen path inspectable and resumable.[cite:32][cite:14]
- **Usage in this thread:** Hall Monitor + Hemingway Protocol were recognized as accepted directions pending rested implementation, which is exactly the kind of choice an ADR should preserve.[cite:32]

### Dewy Receipt

- **Type:** meta decision receipt.[cite:31]
- **Definition:** A receipt for the use of ARCS itself, capturing time, context, prediction, decision, confidence, and next action.[cite:31]
- **Function:** Preserve not just what was decided but under what conditions it was deferred, advanced, or phase-locked.[cite:31][cite:33]
- **Usage in this thread:** “Do not build after midnight; revisit mañana” is a Dewy-worthy decision because it captures resistance to false urgency and protects coherence.[cite:11][cite:31]

### False Urgency

- **Type:** drift pathogen / immune target.[cite:14][cite:11]
- **Definition:** The felt pressure to act immediately despite degraded coherence, weak necessity, or poor timing.[cite:11]
- **Function:** ARCS should detect and dampen false urgency, especially late at night or under token-anxiety, by using Kairos Lock and explicit deferment receipts.[cite:11][cite:14]
- **Mantra surfaced in thread:** “The road to ruin.” This functions as a compact immune cue against low-quality midnight execution.[cite:11]

### 5-Hour Window Budget

- **Type:** session-level budget object.[cite:31][cite:33]
- **Definition:** A finite Claude usage window treated as a mixable allocation problem across planning, testing, refining, executing, and field carry-forward.[cite:33]
- **Function:** Shift the user from ad-hoc usage to deliberate budget orchestration across prompts, operators, and future agents.[cite:33][cite:31]
- **Implication:** The Hall Monitor should eventually reason not only about token cost per prompt but also about how much of the 5-hour window should be spent on planning vs. implementation vs. agent setup.[cite:31][cite:33]

## Working principles from the thread

- Preserve omakase in source artifacts; serve QSR at runtime.[cite:32][cite:33]
- Let Muse/Vestal capture field truth; require sober compression before shipping.[cite:11][cite:33]
- Treat token and time budgets as first-class decision variables, not invisible overhead.[cite:31]
- Stamp meaningful meta-decisions with ADRs and Dewy receipts so tomorrow does not have to re-decide tonight’s insight.[cite:31][cite:32]
- Resist false urgency; defer when coherence is low and preserve a clean restart point instead.[cite:11][cite:31]
