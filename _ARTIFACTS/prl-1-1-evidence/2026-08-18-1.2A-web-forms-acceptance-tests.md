## Pre-build check (do this first, cheap)
1. Confirm the current form plugin on WP staging — prior finding was Gravity Forms, but verify
   it's still the plugin in use, don't assume.
2. Confirm the Webhooks add-on is installed/licensed. If not, that's the one real cost/timeline
   unknown for this addendum — flag immediately, don't silently absorb the delay into the
   existing best/base/worst estimate on `/status/troubleshooting`.
3. Confirm the form's current field list. It may be missing company/state fields entirely
   (prior finding) — if so, adding fields to a form Todd hasn't reviewed is a visible scope
   change; flag before building, don't silently add fields.

## Acceptance tests (in order — each must pass before moving to the next)
1. **Step-level test** (Zapier's own test-run, synthetic data) — confirms the 3-step chain
   (WP trigger -> Code -> SugarCRM) mechanically works. This is necessary but NOT sufficient —
   do not report this alone as "done," same lesson from the chatbot leg.
2. **Real submission test** — submit an actual form on WP staging with realistic data
   (a real name with a title/suffix, a real state, a company name). Independently read the
   resulting Sugar Lead directly (don't trust the Zap's self-reported step output) and confirm:
   - `first_name`/`last_name` split correctly
   - `location_c` is a real code OR the sibling audit field correctly flags a parse failure —
     never a silent wrong-but-plausible value
   - `lead_source: "Web Site"`
   - `account_name` doesn't silently truncate/reject on a long company name (Fix 3 from the
     chatbot leg was deferred as low-risk there — decide here whether it's still low-risk once
     real form data is in play, since forms may allow longer free-text company names than a
     chat flow's captured answer)
3. **Duplicate-submission check** — does resubmitting the same form (e.g. a user double-clicks
   submit) create two leads? Not tested on the chatbot leg since Tidio's flow structure made it
   moot; worth a quick check here since web forms are more prone to double-submit.

## What "done" looks like — bring this back
Same bar as the chatbot leg: one real (non-synthetic) form submission, a Sugar Lead ID from it,
and a plain statement of what was tested vs. assumed. Whoever verifies (co-pilot or Claude) does
an independent Sugar read against that Lead ID before calling it closed — not a trust-the-
step-test sign-off.
