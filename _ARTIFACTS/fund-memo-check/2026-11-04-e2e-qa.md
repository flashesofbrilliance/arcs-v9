# End-to-end test and QA: the memo trace offer (2026-11-04)

Internal. Two parts. First, one end-to-end run of the offer's promised output (memo in, one row per number out)
over an invented fund data room. Second, a check of every factual claim in the three drafts against the code and
live state. All test text is invented. No client or counterpart document was touched. Nothing was sent or committed.

**Verdict:** the drafts hold up, with one material gap. In the run, 1 of 9 memo figures came back **traced when it
was wrong**: the memo's "100%" fee offset matched the "100% catch-up" in the carry clause, while the fee offset
clause says 80%. A figure match alone can land on the wrong clause. A cheap rule fixes it in this case (the clause
must share a subject word with the memo sentence), and the offer's "Traced" line now says "on the same subject".
Every other miss went the safe way: flagged when it could have passed.

## Part 1: end-to-end run

**Setup.** Public engine at head 3fdfb59 (fresh clone), no model, $0. Data room in `e2e/room/`, already restyled to
the format the engine reads (that restyling is the per-client setup work in the fit check):

- an LPA excerpt: term, commitment period, management fee 2.0%, fee offset 80%, expense cap $1,500,000, preferred return 8%, carry 20% with a 100% catch-up
- Amendment No. 1: fee cut from 2.0% to 1.75% (in the wording the engine knows), and the expense cap "amended and restated" to $2,000,000 (LPA wording it does not know)
- a side letter: a 1.50% fee for Investor A

The IC memo (`e2e/memo.txt`) is 8 sentences carrying 9 figures, with planted errors. The expected result for each
figure was written to `e2e/expected.json` before the run. The scratch memo front end is `e2e/bin/trace.py`. It pulls
each figure, searches clauses with the engine's own search, and checks the figure against the governing text. It
uses the engine's own figure match and amendment logic, and is not part of the engine.

Rerun:

```bash
python3 -I _ARTIFACTS/fund-memo-check/e2e/bin/trace.py <engine clone> _ARTIFACTS/fund-memo-check/e2e/room _ARTIFACTS/fund-memo-check/e2e/memo.txt
```

false flag costs reviewer time. A false pass is the failure the offer exists to prevent.

### What the run found

1. **False pass by clause.** "100%" appeared in a clause on a different subject. The check proves the number is in
   *a* clause, not in the clause the sentence is about. Tested fix: require the figure's clause to share at least
   one subject word with the memo sentence. On this run, 9.2 shares no words with the offset sentence and would be
   demoted. The true matches share 3 to 6 words each (`e2e/bin/probe.py`). One case, not a proof. It goes into the
   fund retune and the golden cases.
2. **Feeding memo sentences to the engine as questions does not check the memo.** Run through the engine's own
   `answer()` (mock model), every line came back "answered" with "verbatim ok", the wrong 100% line included. The
   engine answers what the clause says. It never compares that with the memo's figure. The comparison step is new
   build work (fit check limit 7). This run confirms it.
3. **Side letters are invisible.** Investor A's 1.50% sits in the room but was never raised against line 1. The
   engine has no idea of "for this investor". As the fit check said: new logic, and the riskiest piece.
4. **LPA amendment wording fails safe but noisily.** "Amended and restated" was unresolved, which is correct. But
   the review note rode along on any line whose search touched 8.3 (lines 2, 3, 5, 7), not only the expense line.
   Expect reviewer noise until amendment readers exist for the client's wording.
5. **Worked-out numbers are not sorted.** $437,500 and March 1, 2031 came back plain "not covered". Telling a
   computed number apart from an unsupported one is not built. Until it is, a person sorts that bucket.
6. **Words vs digits.** "10 years" vs "ten years" false-flagged, like "2%" vs "2.0%" in the earlier probe. Same
   value normaliser item.
