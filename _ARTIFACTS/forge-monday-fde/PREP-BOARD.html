Round-robin: strophe, antistrophe, epode

Strophe top-down: does the story hold as detail increases? Antistrophe bottom-up: is every claim supported one level down (the claim ladder)? Epode: reconcile conflicts by layering and linking, book each change as a seam. Two rounds, then stop. Process gatekeeper (recruiter): policy breaches disqualify before anyone reads it.

Research map monday GitHub, Hugging Face, docs: static reads, nothing run

Confidence key: verified read in source or docs, inferred reasoned, not found. Respectful framing: say what an eval needs next, never what is broken.

verified What monday publishes

  • MCP server and agent toolkit (open), plus a hosted MCP whose source is not public
  • Agent Tool Protocol: code-first alternative to tool calling
  • agentic-monday: Claude Code plugin marketplace
  • Vibe design system, apps SDK and CLI
  • Developer docs with machine-readable llms.txt pages
  • Models API: OpenAI-compatible gateway; OpenAI and Anthropic upstreams

inferred What it suggests

  • Sensei looks dormant since March 2026 and is not in monday's docs index
  • Hosted MCP controls cannot be audited from public code
  • Most tests are mock-based; no live-account or agent-behavior tests
  • The deployment function was formed from Professional Services
  • Deployment work reaches into the sale (scoping, estimates, SOWs)

not found

  • An official monday Hugging Face organization (API returned none)
  • A public report on this exact take-home or an accepted-offer story for this track
  • Self-service per-tool-call audit export for MCP
  • A published harness for the routing eval (404s)
Sensei read in source (not reproduced)
  • Good: clean YAML suite schema, transparent scoring (50, 30, 20 layer weights), deterministic KPI primitives, seeded pools, HTML report.
  • The judge never sees the fixtures; two of four adapters drop fixtures; the agent model name is fixed; no clamp on scores; a judge outage becomes a zero.
  • Layers 2 and 3 are thin (a fresh prompt, a static feedback string); shipped suites cover SDR, support and content only.
  • Falsify before you say any of this: run one suite with the judge prompt logged, try a stub adapter, a score of 15 on a 10-point scale, a model: key, and multi_judge. Strike whatever does not reproduce.
Do not claim
  • That sensei is monday's standard, adopted or maintained; or that monday has a Hugging Face presence.
  • That any code, test or eval was run; counts are grep-based and drift daily.
  • That ARCS calibration is proven (outcome capture is low) or that ARCS is certified or compliant.
  • That monday's hosted MCP lacks or enforces a control; or that monday has no audit at all (say "no self-service per-tool-call export").
  • Anything about a named maintainer, or the default-secret finding in a protocol repo (a private maintainer matter, not interview material).

Consonance spine, kairos, and what compounds

Put first what many altitudes want. Treat compounding as a hypothesis with a falsifier; say "compress time to value," never "exponentially."

Spine (lead with these)

  • Time to first value, with a baseline and target
  • A repeatable playbook or offering
  • An EBR-style one-pager of adoption and outcome
  • Quality at full coverage with a stated pass bar
  • Governance in proportion to the scenario
  • AI-assisted building shown plainly, reasoning logged

Five time-signature questions

  • Why now (kairos)?
  • Why this instrument?
  • Can you actually play it? Show receipts, not comparisons
  • Does this make my life easier? Say it in each altitude's currency
  • What compounds?

Compounding menu (pick one or two after the brief)

  • Engagement playbook: days to first value, engagement one versus two
  • Discovery and friction-audit template: hours to a ranked list
  • Connector patterns with read-after-write checks: defects per integration
  • Agent qualification harness fixing known gaps: runs to a stable pass rate
  • Receipts per engagement; governance pack; land-and-expand map

Hard gates and scored dimensions rubric v0: reconcile after you read the real checklist

Any hard gate failing is a KILL: fix or cut, never average. Two audience bars must both clear: Bar A (customer outcome) and Bar B (builder defense). The author never self-clears; an independent bar-raiser issues CLEAR, CONDITIONAL CLEAR or HOLD.

Hard gates

H1On time (target Oct 14 evening)
H2One ZIP under 10 MB; source/ and presentation/ non-empty
H3Every portal checklist item complete
H4Video watched, pre-read reviewed, dated notes
H5Same browser and device; no incognito, no cookie clearing, no forwarding
H6Confidentiality: no secrets, PII or private IP
H7Every AI use logged; every file explainable
H8Provenance and consistency pass
H9Brief answered against written acceptance criteria
H10No silent repair (kintsugi entry per fix)
H11No unrun claim stated as fact
H12Respectful framing of monday's own work

Scored dimensions (0 to 3)

AOutcome framing; scoping and assumptions; adoption and rollout; governance (if relevant); communication; reusability
BBuild quality; evidence it works; defensibility; time discipline
A+BHonest limits
A bar clears at 2 or more on every dimension and a 2.3 average; both bars must clear.

Red and blue, bounded

Round 1: a fresh agent given only the brief, the rubric and the draft, told to refute. Fix, logging each seam. Round 2 only if round 1 returned a HOLD. Then stop. If a section still fails and time is short: cut it.
