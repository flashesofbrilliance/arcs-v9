Engine robustness gauntlet

BAR / ruin · does it survive being wrong

Root pattern: parse_story enforced only presence and a few enums. Every other constraint the schema advertised (hex pattern, id pattern, AA contrast, uniqueness, label bounds) was documentation the engine never checked. Text fields were escaped; hex was the one field reaching an HTML sink raw.

01

Stored XSS via unvalidated, unescaped thread hex

HIGHFIXED
story_render.py · _node / arc_horizontal / braid_svg / endmark_svg / thread_legend / ladder color
Defect
The hex string is interpolated raw into fill="..." / stroke="..." / style="color:..." in every SVG mark, with no h.escape and no check against the schema's ^#[0-9A-Fa-f]{6}$. A poisoned palette breaks out of the attribute and injects a live <script> into a page published on good.arcs.care. Text fields (label, name, caption, body, title) are all correctly escaped; hex was the single sink left open.
Repro
thread gold with "hex":"#FFD700\"><script>alert('hex')</script>"
-> endmark SVG renders: <circle ... fill="#FFD700"><script>alert('hex')</script>"/>
Fix
In parse_story, enforce re.fullmatch(r'#[0-9A-Fa-f]{6}', hex) and raise StoryError. Closes the injection and the schema's unenforced hex pattern in one check.
Verdict / heal
Validation battery added to parse_story: hex is now pattern-checked at parse time; a malformed hex is refused before any render.
02

Schema's 'must clear AA' contrast claim was unenforced

MEDFIXED
story_render.py · parse_story · nftt-story.schema.json (hex description)
Defect
The schema states each hex 'Must clear AA on the void background,' but nothing computed contrast. hex #050505 on the #020408 void rendered fine, exit 0. An invisible node/stitch/chip could ship as if legible, violating earned-fidelity doctrine (the brief never lies about how certain it is).
Repro
hex:"#050505" -> renders, exit 0, fill="#050505" present, nodes effectively invisible.
Fix
Compute WCAG relative-luminance contrast vs #020408 in parse_story; refuse below 3:1 (large-glyph AA).
Verdict / heal
contrast() helper added; parse_story refuses any thread hex below 3:1 on the void. Ship-gate #5 is now mechanical, not documentation.
03

Horizontal arc had no label-length bound; long labels overflow

MEDFIXED
story_render.py · render_arc / arc_horizontal
Defect
The Bierut legibility gate (ARC_MAX_HORIZONTAL_STOPS) gated the NUMBER of stops, not label length. SVG width is computed from stop count, and SVG <text> never wraps. A 2-stop arc with a 400-char label renders one line far past the column and the mobile viewport, the exact failure the gate exists to prevent, on a different axis.
Repro
2 stops (stays horizontal), one label 400 chars -> SVG width=218 but text runs off-viewport.
Fix
Add a label-length ceiling: force the vertical ladder when any horizontal-form label exceeds ~24 chars, mirroring the count gate.
Verdict / heal
render_arc now reflows to the ladder when any label exceeds the char ceiling OR stop count exceeds 6. The legibility gate now guards both axes.
04

Duplicate thread ids accepted; refs silently bind to the last one

MEDFIXED
story_render.py · parse_story / tmap builders
Defect
tmap = {t['id']: t for t in threads} is last-wins, so two threads with the same id mean every stop referencing that id silently binds to the second declaration, and the legend prints two same-id chips. No error.
Repro
two threads both id:"red" (circle/#FF4D6D vs square/#00FF9D) -> renders, arc binds to the second silently.
Fix
if len(set(ids)) != len(threads): raise StoryError('duplicate thread id').
Verdict / heal
parse_story now refuses duplicate thread ids.
05

6+ threads: braid and endmark were hardcoded to 3; extra threads vanished

LOWFIXED
story_render.py · braid_svg (range(3)) / endmark_svg (min(3, len))
Defect
The legend renders all N chips, but the braid emitted exactly 3 paths and the endmark min(3, len) marks. A story declaring 7 threads visually claimed 3, a quiet honesty gap between legend and braid, against the schema's 'two to N threads' promise.
Repro
7 threads -> legend shows 7, braid shows 3, endmark shows 3.
Fix
Loop braid and endmark over ALL threads (or refuse >N explicitly so the omission is a decision).
Verdict / heal
braid_svg and endmark_svg now iterate every declared thread; the marks reflect the real palette count.
06

Long thread names never wrap (legend + ladder column)

LOWFIXED
story_render.py · thread_legend / .arc-thread (white-space:nowrap)
Defect
Legend chips and the ladder thread column set white-space:nowrap with no clamp; a very long name overflows the key box or pushes the ladder grid column.
Repro
120-char thread name -> overflows .threadkey box.
Fix
Cap name length in parse_story (or add ellipsis).
Verdict / heal
parse_story now caps thread name length; an over-long name is refused at parse time.
07

Survives being wrong (the passes)

EARNS ITKEPT
story_render.py
Verdict / heal
[[ARC]] with no arc defined: dropped cleanly, no crash. Empty body: renders shell + endmark. Stop referencing a thread by name not id: correctly refused. 45-stop arc: reflows to a legible vertical ladder. HTML injection in label/name/caption/body/title: all correctly escaped. Only hex reached a sink unescaped (finding 01).

Michael Bierut design adversary

editorial rigor · five-second test · idea over decoration

The bones are sound and the arc reflow gate is genuinely smart. The defects cluster in one place: ornaments that repeat identically regardless of content, and one of them (the gradient tick) is not even wired to the story's own data.

01

The per-section gradient tick is hardcoded decoration that lies about the data

KILLFIXED
story_render.py · CSS h2::before / .pull::before
Defect
The whole engine's thesis is 'threads are data, a story picks its own.' braid and endmark honor that. But this tick is a literal constant: linear-gradient(90deg, var(--red), var(--gold), #FF6B2C). Any story with a different palette still gets a red->gold->verm bar under every heading and pull-quote, describing a palette the story does not use. The single most-repeated ornament is the one wired to the wrong data, and it is literally broken for the general case. Even for this story it means nothing: identical under all 7 H2s, telling the reader nothing 7 times.
Repro
The custom cyan/red extensibility test (two-thread.html) still contains the red/gold/verm tricolor tick, x2.
Fix
Drive the tick from the story's actual threads (a gradient built from the declared palette), or color each section's tick by its governing thread as wayfinding. If not wired, delete both ::before rules; the type hierarchy stands without them.
Verdict / heal
Tick gradient is now built from the declared threads and injected as a CSS variable; a cyan/red story gets a cyan/red tick. Section and pull-quote ornaments differentiated (finding below).
02

Arc-ladder mono thread-label names the color in its own color

KILLFIXED
story_render.py · arc_ladder · .arc-thread
Defect
Each ladder row already encodes the thread three ways (glyph shape, glyph color, legend). The mono label was a fourth encoding adding zero information, a red word that says 'RED.' And it took name.split('·')[0] (the color-name half) and threw away the meaning half ('gates'). It labeled the color by its color, not by its role. Monospace-as-costume on a label carrying no system information.
Repro
arc ladder rows render 'RED' / 'GOLD' / 'VERMILLION' right-aligned in the thread color.
Fix
Show the ROLE not the color-name: name.split('·')[1] -> GATES / ASSETS / FUSION, which the glyph genuinely cannot say. Never both the color and its name.
Verdict / heal
Ladder right column now shows the thread ROLE (gates/assets/fusion), the one thing the glyph cannot carry.
03

The declared eyebrow envelope field never renders (dead control)

MEDFIXED
story_render.py · build() reads eyebrow, never passes it to PAGE
Defect
A carefully-written envelope field that produces nothing. The eyebrow's job is instead done by the body's # line, with different wording. Two competing eyebrow sources, one inert. The next author edits eyebrow, expects a change, gets none.
Repro
eyebrow present in envelope, absent from rendered HTML.
Fix
Pick one source. Render {eyebrow} in PAGE and drop the # convention, or delete eyebrow from schema and build().
Verdict / heal
eyebrow removed from build() and the schema; the # body line is the single documented eyebrow source.
04

The braid SVG does not braid, and is hardcoded to 3 strands

MEDFIXED
story_render.py · braid_svg (range(3), all paths terminate at 196 18)
Defect
All three strands terminate at the same point: three wires merging into one plug, crossing once. A braid interweaves repeatedly. At a glance it reads as a squiggle, failing the very test the section name ('The braid') sets up. Hardcoded to 3 despite the N-thread promise (overlaps robustness finding 05).
Repro
'The braid' section emits 3 converging paths regardless of thread count.
Fix
Make it genuinely interlace (multiple crossings, strands emerging on the far side, count from len(threads)), or cut it; the heading plus the colored thread-summaries already deliver the idea.
Verdict / heal
braid_svg rewritten as N phase-offset woven strands driven by the declared threads; adjacent strands actually cross.
05

Pull-quote and section-head wear an identical ornament

MEDFIXED
story_render.py · .pull::before and h2::before (same gradient)
Defect
A pull-quote and a section header are different structural ranks but wore the same gradient bar. The reader's eye cannot use the ornament to tell 'new section' from 'emphasis pull'; one signal spent on two ranks.
Repro
Both ::before rules render the same tricolor bar (34px vs 48px).
Fix
Give them different marks: thread-gradient bar for sections, a single accent rule for pull-quotes.
Verdict / heal
Folded into the tick fix: section tick = full thread gradient; pull-quote = single first-thread accent. One ornament, one meaning.
06

Full prose sentences set in monospace (the 'stitch' lines)

LOWBY DESIGN
story_render.py · .stitch
Defect
Complete first-person sentences in JetBrains Mono. Mono earns its place on system tokens (footer, nav, legend); a voiced sentence is voice, not label. A near-miss: the conceit (stitch = system annotation on the narrative) is coherent, so not a kill.
Repro
Thread stitches render authored sentences in mono at .82rem.
Fix
Optional: keep the mono thread-marker and color, set the sentence in sans italic.
Verdict / heal
Kept by design. The stitch-as-machine-annotation conceit is deliberate and matches the frozen post-1/post-2 reference aesthetic; changing it would diverge the family. Logged, not changed.
07

Elements that earn their place (checked, not cut)

EARNS ITKEPT
story_render.py
Verdict / heal
The endmark glyph: a genuine wordless colophon that reads from the actual threads. The arc reflow gate (horizontal <=6 -> vertical ladder): the five-second test made mechanical, the best idea in the file. The thread legend mapping color+shape to named role, placed before the first stitch. Mono on the depth-nav and footer: proper system voice, not costume.

Template claims skeptic

adversarial verifier · behavior over comments

Five of six claims hold as behavior, not just prose: genuinely data-driven, honesty gates truly refuse with exit 1 and write nothing, the arc reflows past the threshold, the reference render is byte-identical with full prose parity, analytics and meta description are emitted. The one claim to distrust as stated is 'zero em-dashes.'

01

TRUE: extensible + data-driven

EARNS ITKEPT
story_render.py · parse_story / build
Verdict / heal
threads and arc read from the JSON envelope; nodes/legend/braid all take the thread hex/shape. A 2-thread non-NFTT story with custom hex (#3366CC / #22AA88) rendered exit 0, custom hex present, no NFTT colors used. Schema enforces minItems 2, no max.
02

TRUE: the legibility gate is mechanical (with a caveat now closed)

EARNS ITKEPT
story_render.py · render_arc (ARC_MAX_HORIZONTAL_STOPS=6)
Defect
The gate was a fixed stop-COUNT threshold, not a measured label-width check: a 6-stop arc with very long labels was not caught (see robustness finding 03).
Fix
Add the label-length axis to the gate.
Verdict / heal
6 stops -> horizontal, 7 -> ladder, 12-stop reference -> ladder. Label-length axis added in the kintsugi pass so the count-proxy gap is closed.
03

TRUE: honesty gates refuse with exit 1 and write nothing

EARNS ITKEPT
story_render.py · StoryError -> sys.exit(1) before any write
Verdict / heal
All four refusal paths tested: missing envelope, <2 threads, undefined arc thread ref, bad shape. Each exit 1 with no output file written.
04

'Zero em-dashes' was TRUE for the artifact but NOT enforced

MEDFIXED
story_render.py · no em-dash check anywhere
Defect
The rendered output had 0 em-dashes, but there was no mechanism: a story whose body prose contains an em-dash renders it verbatim (reproduced count=1). Per ADR-034 this is verified-as-PROSE, not a gate. If 'zero em-dashes' is an invariant, nothing caught a violation.
Repro
story body containing an em-dash (U+2014) -> output contains that em-dash (count=1), exit 0.
Fix
Refuse the render (StoryError, no output) if the assembled page contains an em-dash.
Verdict / heal
build() now scans the assembled page for the em-dash character and refuses to write if any is present. Ship-gate #1 is now mechanical: no story can ship an em-dash, prose included.
