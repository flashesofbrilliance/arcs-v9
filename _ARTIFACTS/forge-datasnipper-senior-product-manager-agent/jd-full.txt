ABOUT THE ROLE:

Auditors sign their name to every conclusion. An agent can do the heavy lifting, but only if the auditor can see how each conclusion was reached and trace it back to its source.

Agent Builder is where firms turn their own procedures into agents their whole team can run, in Alwin by DataSnipper, our agentic automation platform for audit and finance. Built well, an agent makes quality a property of the procedure, not of who happened to be staffed on the engagement.

You'll own Agent Builder and the agents firms build with it. Your users are the people at firms who build agents, and the methodology and quality teams who approve them for client work.

This is a technical PM role. You'll shape the harness each agent runs in: the context it sees, the tools it uses, and where a person reviews its work. You'll own the feedback loops that improve agents after release. You'll work as a peer to a new engineering team in New York, and with our Agent Runtime and Evals teams in Amsterdam.

THE PROBLEMS YOU'LL OWN

 - Knowledge and context: how a firm's methodology, guidance, templates and prior work are captured, kept current, permissioned and served to agents at the moment they need them

 - Definition: the authoring experience and the definition model that turn a procedure into a multi-step agent: steps, tools, knowledge sources, thresholds and human-in-the-loop gates

 - Test and publish: how builders evaluate an agent against real cases before it ships, and the review and approval it passes before it reaches the Agent Library

 - Run and observe: tracing what an agent did on a live engagement, which knowledge it used and why

 - Govern, version and retire: permissions, change history, approvals, rolling out new versions without breaking work in progress, and retiring agents and outdated knowledge cleanly


WHAT YOU'LL DO:

 - Own the Agent Builder strategy and roadmap, and make the trade-offs explicit

 - Design the harness with engineering: how context is assembled, how tools are defined and called, and where a person must review

 - Decide what builders control and what the platform sets, so agents can encode real methodology and stay consistent

 - Build the feedback loops: turn run traces and reviewer edits into eval cases, regression tests and changes the firm approves

 - Set the quality gates an agent must pass before release, and test every new model or methodology version before it reaches live work

 - Report agent quality with a stated method and sample

 - Prototype in code before you write specs. Then write short specs and decision memos that engineers can build from

 - Spend time with the firms that build and approve agents, and turn what our forward-deployed teams learn into product, not one-off fixes
