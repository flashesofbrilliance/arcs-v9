SEC 1

General

ARCS produces artifacts — call briefs, reports, and decision receipts served as static pages on *.arcs.care. This manual covers how those artifacts are built, verified, and deployed. It is written for whoever is operating the tooling next: Zach, or a cold-started Claude session with no memory of the last one.

1.1  Governing law

One rule outranks everything else in this manual:

Note — Prime Directive Every provenance claim on an ARCS artifact must be executable. If a page says a command produced it, running that command must reproduce the page byte-for-byte. Never stamp an artifact with tooling that does not exist — that is provenance theater, and the first technical viewer who tries it converts a transparency claim into a credibility hole. (ADR-032.)

SEC 2

Limitations

Operating limits. These are not style preferences; each one exists because violating it has already caused, or provably would cause, an incident.

#LimitReason
L-1 Client-facing briefs carry provenance: "receipt" only. The full tier (visible CLI card) is internal artifacts only. Exposing internal command surface on a client page violates the engagement redaction rules (no vendor/tooling stack on target pages).
L-2 Params files live in briefs/ — never under public/. Everything in public/ is served. Params contain the gate password and pre-redaction content.
L-3 Rendered HTML is never hand-edited. All changes go through the params file. Hand edits are drift by definition; --check will flag the file and the next render will silently destroy the edit.
L-4 Adoption is forward-only. The 13 pre-ADR-032 briefs are not backfilled unless one becomes an active demo. They are bespoke, diverged, and live in front of clients. Extraction is clobber-risk for near-zero payoff.
L-5 Production deploys run from the main worktree (/Users/zharris/arcs-v9 checkout of main) — never from a feature worktree. Each worktree has its own next.config.ts; deploying from one silently drops every other subdomain's rewrite.
L-6 Engagement artifacts get a redaction scan before every deploy: no comp bands, no vendor stack, no back-links to internal pages, no verbatim attributed quotes. Standing security constraint from the Fanatics engagement; generalized to all client artifacts.
SEC 3

Normal Procedures

N-1Create a new call brief (CLI path — preferred)

Params file AUTHOR briefs/<name>.params.json
Copy briefs/demo.params.json as the schema reference. Set name (lowercase first name = gate password), slug (output file stem), and the four tab card arrays.
Provenance tier SET per L-1
External viewer → "receipt". Internal/demo → "full". Omitted defaults to receipt (fail-safe).
Render RUN from repo root
$ python3 scripts/brief_render.py --params briefs/<name>.params.json
rendered public/<slug>.html (17980 bytes, provenance=full)
Output INSPECT in browser
Serve via npm run dev, open /<slug>.html. Gate password is the name field.
Integrity --check · EXIT 0
Registry UPDATE snapshot.json → ui_artifacts
Commit PARAMS + HTML TOGETHER
Both files in one commit, or drift detection loses its anchor.

N-2Amend a generated brief

Edit target PARAMS FILE ONLY (L-3)
Re-render RUN N-1 render step
Verify --check · EXIT 0

N-3Verify artifact integrity (drift check)

$ python3 scripts/brief_render.py --params briefs/<name>.params.json --check
OK — public/<slug>.html matches its params (no drift)

Run before any deploy that touches generated briefs, and any time a generated page looks different from what its params say.

N-4Deploy a brief to a subdomain

Worktree CONFIRM main checkout (L-5)
git worktree list — find the worktree on main (historically frosty-kepler-b69f51). Never deploy from a feature worktree.
Rewrite ADD to next.config.ts beforeFiles
{ source: '/', destination: '/<slug>.html', has: [{ type: 'host', value: '<name>.arcs.care' }] }
Redaction scan COMPLETE per L-6
Commit & push MAIN · AUTO-DEPLOYS
Domain VERIFY 200 on <name>.arcs.care
If the subdomain 404s, it may need assignment to the arcs-v9 Vercel project in the dashboard.
SEC 4

Abnormal Procedures

A-1DRIFT DETECTED — --check exits 1

brief_render: error: --check: public/<slug>.html has drifted from its params
Cause IDENTIFY — git diff the HTML
Either someone hand-edited the output (most likely), or the template / generator changed since last render.
Hand edit worth keeping? PORT into params, re-render
Hand edit accidental? RE-RENDER — overwrites it
Template/generator changed? RE-RENDER ALL generated briefs
Caution Re-rendering destroys hand edits without asking. Decide what the edit was before running the render.

A-2Unresolved placeholders / missing tab

brief_render: error: params.tabs missing tab 'agenda'
brief_render: error: unresolved placeholders after render: {{YGATE}}

The renderer refuses to write partial output. All four tabs (pre / recoil / post / agenda) need at least one card; all eight metadata fields are required. Fix the params file — never relax the guard.

A-3Unknown card type

brief_render: error: unknown card type 'bogus'

Card type must be one of the six in section 5.3. For a section shape none of them fit, use "type": "html" — the escape hatch exists so bespoke content never requires editing the output by hand.

A-4Subdomains dropped after a deploy

Warning Symptom: previously-live *.arcs.care briefs suddenly 404. Cause: a deploy ran from a feature worktree whose next.config.ts lacks the other rewrites (L-5 violation).
Recovery REDEPLOY from main worktree
Confirm 200 on ALL registered subdomains
The full roster is in _STATE/snapshot.json → ui_artifacts.call_briefs.
SEC 5

Systems Description

5.1  Brief Rendering System (ADR-032)

A deterministic, stdlib-only renderer. Same params + same template ⇒ byte-identical output, which is what makes the embedded provenance provable rather than asserted: anyone with the repo can re-run the printed command and diff.

ComponentPathRole
Rendererscripts/brief_render.py params + template → HTML; validates; refuses partial output
Canonical templatepublic/templates/call-brief-template.html v1.1 · atoms + tab markers; hand-authoring path still valid
Params (source of truth)briefs/<name>.params.json Open JSON contract; git-tracked; never served
Outputpublic/<slug>.html Generated artifact — read-only by convention (L-3)
Proof artifactpublic/demo-brief.html Self-referential demo; footer shows the command that made it
Registry_STATE/snapshot.json → ui_artifacts Roster of live briefs + authoring workflow

5.2  Provenance system

TierAudienceRenders as
fullInternal / demo Visible card: the exact CLI invocation, template version + SHA-256, params SHA-256, and the byte-for-byte reproducibility claim
receiptClient-facing (default) One mono footer line — ARCS · call-brief-template v1.1 · params 43380f7e24e0 · Jul 10, 2026 — no command surface

Both tiers also embed a machine-readable HTML comment (arcs:brief-render …) with template version and both hashes.

5.3  Card types

TypeFieldsUse for
texttitle, textTrue North, prose blocks
conftitle, rows[key, val | badge] Context / logistics; badge renders the Y-gate pill
inteltitle, rows[color, text] Key facts with colored dot markers
questionstitle, rows[text, look_for?] Numbered questions; auto-numbered
nexttitle, rows[owner, color, text] Action items by owner
htmltitle, html Escape hatch — any bespoke section

Colors: cyan · green · gold · red · muted · dimmed → the template's CSS variables. Text values are trusted HTML fragments — author-controlled, never user input.
