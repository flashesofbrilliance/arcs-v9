03
KEY LEARNINGS — PIVOTS & CORRECTIONS
The build is honest about where it was wrong.
Paying down false-claim debt
A self-audit found the project's own written rules had zero real enforcement — including a "no Tailwind" rule violated since day one by scaffold remnants sitting in the build. Response: remove the dead framework, align docs and CI to reality, then institutionalize it — findings now close only via an enforcement mechanism or a dated, signed waiver in a CI-gated ledger.
Rules without enforcement are decoration. Audit the gap, then make the gap impossible.
Security theater vs. real isolation
The textbook Postgres row-level-security pattern would have passed any checklist review and protected nothing — the ORM connects as a superuser that bypasses row policies entirely. Chose deny-all policies plus app-layer isolation instead, and wrote down exactly why the "correct-looking" option was rejected.
Security posture must match the actual connection topology, not the reference architecture diagram.
Trust means no silent writes
Anonymous visitors' compass runs were being persisted without an account — legal-ish, but off-covenant. Shipped the subtraction first (cut the anonymous write path entirely), then rebuilt saving as an explicit opt-in, and versioned the public trust contract to match.
When behavior and stated values diverge, ship the deletion before the feature.
Red-team the architecture doc, not just the code
The observability architecture (an inferred goal-lattice over decision receipts) went through an independent adversarial review before acceptance — which corrected four over-claims in the design doc, including a theorem that didn't exist. The corrected version shipped; the flattering version didn't.
Design documents hallucinate too. Evaluation discipline applies to prose.
Aborting a migration is a decision, not a failure
A typed-config migration was deliberately halted mid-flight when it emerged that merging would silently drop production cron and service routes added concurrently on main. The abort, the reason, and the resume conditions were written down instead of forcing the merge.
Velocity includes knowing when not to merge. An aborted change with a receipt beats a shipped regression.
Verify live, not from memory
Documentation claimed two domains were served by two different codebases; a live infrastructure check proved both had silently consolidated onto one deployment. Now a standing protocol: any claim about what production is doing gets re-verified against the platform API before anyone relies on it.
Docs record the past. Production is the only source of truth about production.
