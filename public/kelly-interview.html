SIGNAL — Competitive Intelligence System
Operational alpha for your own team's competitive blind spot.
Two agentic layers. MCP enrichment. Role-based presentation. Deterministic evals. No scraping. No ToS risk. Built from Juniper's own playbook — applied to the gap they hadn't named internally.
▸ CEO Alex's direct mandate: scan ~40 competitors, surface proactively to internal teams.
Two registers — same system
Executive
CEO gets a 30-second digest. CRO, CMO, CFO each get different data at different resolution — persona-mapped from day one. Sales walks in with last week's battlecard. When a competitor ships a feature, changes an exec, or posts a security incident — you find out that day.
Technical
Two agentic layers: looking out (market intel, positioning, TAM, share of voice) + looking in (feature parity via browser/agent automation). MCP enrichment: Gartner, CB Insights, Privco, Clay. Triggers via Vercel edge functions + Google News Alert connectors. Deterministic, falsifiable evals at every layer.
Architecture — six layers
01
Sources
OUT →
Competitor press rooms, changelog pages, G2/Capterra reviews, SEC EDGAR filings, job posting pages (not profile data), company social accounts, your own CRM deal notes.
IN →
Feature parity gap analysis via Playwright / Stagehand / Browserbase — what competitors have shipped that Juniper hasn't. Note: verify ToS on target product UIs before automating; scope this layer collaboratively with the team, not unilaterally.
02
Triggers
Vercel edge functions + Google News Alert connectors. Event watchers: new competitor post → fires · 5+ AI/ML hires in 30 days → fires · exec change · funding round · security incident · G2 review mentioning pricing. Trigger = signal, not noise.
03
Enrichment
MCP layer pulls third-party context per event. Tier A (if subscriptions exist): Gartner (analyst positioning) · CB Insights (funding/market data) · Privco (private company financials). Tier B (default, no subscriptions needed): Clay enrichment + public sources — covers ~80% of the competitive signal at zero marginal cost. Start here, upgrade as needed.
04
Processing
Claude claude-sonnet-5 per event. Constitutional guardrails defined upfront with non-technical stakeholders. Four outputs: who (competitor) · what (signal type: product/pricing/hiring/exec/security) · relevance score 1–5 · stakeholder tag (CEO/CRO/CMO/CFO/product).
05
Outputs
Presentation layer fully abstracted from backend. CEO: 30-second Slack digest, 3 bullets. Analyst: deep drill-down view, full sourcing. Sales: auto-updated battlecard (what changed this week). Product: feature gap log from competitor reviews + browser intelligence.
06
Evals
Deterministic and falsifiable — not vibes. Recall: did we catch event X within Y hours? Precision: is competitor classification correct? Grounding: is summary faithful to source? Coverage: are all 40 target competitors being monitored? Weekly eval report. Thresholds trigger human review.
The LinkedIn fix
Their existing system scraped profile data — personal work history, contact info. That's the ToS violation. Job posting pages are different. Progressive enrichment options already scoped: LinkedIn API access, Frontspace, Privco API, Clay enrichment. Signal quality from job postings + enrichment APIs is equivalent to profile scraping without the legal exposure. The fix isn't a workaround — it's a cleaner architecture with a clear upgrade path.
