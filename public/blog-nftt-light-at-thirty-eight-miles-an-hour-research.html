Stopped Light Field Notes

You cannot hold light. You can pour it into matter, hold the matter, and pour it back out, if you do it slowly and protect it from noise while it waits. Most of what ARCS gets wrong about memory is that same sentence.

II · The physics

Seven ideas, without the jargon wall

EIT (electromagnetically induced transparency)
A strong control laser makes an opaque atom cloud transparent to a weak probe beam. The window is narrow, and a narrow window slows the pulse sharply.
Adiabatic
Changed slowly compared with the system's own timescale. Fast changes lose information; slow ones transfer it.
Coherence time and decoherence
Stored information fades as each atom's phase drifts at its own rate. Storage time depends on protecting phase, not on holding atoms.
Spin echo and dynamical decoupling
A well-timed flip pulse makes drifting atoms run the drift backwards and line up again. Repeated flips cancel slow noise.
ZEFOZ
A magnetic setting where the stored state is, to first order, insensitive to field noise. Store in a form the noise cannot reach.
Atomic frequency comb
The absorption spectrum is carved into evenly spaced teeth before the light arrives. The spacing fixes in advance when the light comes back out.
Heralding and repeaters
A memory signals "stored". A repeater links short segments independently, holds each until both ends herald, then joins them in one irreversible step.

Adjacent and orthogonal

Negative time (Toronto, 2024)
The time a transmitted photon spends exciting atoms equals the group delay, which can be negative. Nothing travels faster than light; the pulse is reshaped.
Time reflection (CUNY, 2023)
Change a medium abruptly in time and part of a passing wave reflects backwards, with its frequencies converted.
Quantum Zeno effect
Measure a system often enough and it stops evolving. The wrong rate can speed decay instead.
Memory as a learning resource (Science, 2022)
Storing quantum states and comparing them together can learn from exponentially fewer experiments than measuring each one right away.
IV · Isomorphisms

Fifteen echoes, each labelled

A mechanism is the same rule, so a design lesson can carry over. A metaphor is a useful lens that nothing should be built on.

I1Polariton dialmechanism

Live conversation is light; the committed record is matter. Write the durable record while the session is live. End-of-session summaries switch the control laser off at once and scatter what matters.

I2Revival in a second cloudmechanism

The 2007 transfer worked because both clouds shared one laser. Handoffs must carry the bearing and the reason, and the receiving session must read them in the same frame.

I3Decoherence, decoupling, ZEFOZmechanism

Claims go stale the way stored phase does. Re-check on a schedule, and cite in a noise-proof form: content hashes and paths, never "latest" or "currently".

I4Spin echomechanism

Parallel sessions drift apart like atoms in different surroundings. Reconcile before the drift is permanent, on a cadence shorter than the drift time.

I5Frequency combmechanism

The comb fixes recall time at write time. Every receipt should carry its own recall date, derived from the horizon it already records.

I6Memory as a vectormechanism

Score memory on several axes and never total them. A single number hides the trade-off between lifespan, recall and cost.

I7Heraldingmechanism

Build only on links that announced success. The herald must come from the system that did the write, never inferred by the reader. The session behind the essay broke and then honored this rule.

I8Repeater swapmechanism

Segments herald independently, then one irreversible step joins them. Do not commit end to end until every segment heralds; declare the one-way door, then fire it once.

I9Rydberg blockademechanism

Inside a radius only one excitation can exist. Name the scope where concurrent writes are refused. The numbering oracle already is one.

I10Quantum Zenomechanism

Measuring too often freezes evolution. Every re-check schedule needs a ceiling as well as a floor. This one is new to ARCS.

I11Store, then comparemetaphor

Summarizing each item on arrival is like measuring it: the collapse is permanent. Keep raw spans and compare later. The exponential gain is quantum-only; the direction still holds.

I12Negative group delaymetaphor

A reshaped distribution can make an average look impossible. When a dashboard metric reads impossible, look at individual items, not the mean.

I13Time reflectionmetaphor

An abrupt change in the medium reflects waves already in flight. When a project's ground shifts, flag every open decision in it.

I14Warm vapor shipsmetaphor

The 5% room-temperature memory ships; the cryogenic record stays in the lab. Prefer the tool that runs anywhere.

I15Light into soundmetaphor

Moving light into slow sound waves extends storage, and refreshing it adds noise. Store in the slow medium (git, not chat) and refresh on a schedule.

V · Inventions

Five ideas, ranked, each with a kill condition

Each kill condition was written before any build. If the test fails, the idea is withdrawn rather than defended.

Rank 1A ceiling on re-checks

From the Zeno effect. ARCS's freshness proposal says how often a claim must be re-checked at minimum and sets no maximum. Give every live claim a band: often enough to catch real change, never so often that checks find nothing and freeze the work.

Kill iffewer than 20% of past re-checks came back empty.

Rank 2Receipts that know when to come back

From the frequency comb. Each receipt already records a horizon. Derive a recall date from it when the receipt is written and fire the debrief then. Today 2 of 247 receipts have a recorded outcome.

Kill if30 receipts reach their recall date with no lift over 2 in 247.

Rank 3Seven-axis memory scorecard

From the memory scorecard. Score handoffs, memory files, witness notes and the Librarian's picks on recall, accuracy, lifespan, write speed, capacity, false recall and deployability. Report a vector, never a total.

Kill ifone store wins every axis, since the scorecard then collapses to a single number.

Rank 4Handoffs that carry the bearing

From revival in a second cloud. Give a fresh session only the handoff note and ask for the next move and why. Score agreement with the author's bearing, not fact recall.

Kill ifbearing agreement is already high on 3 recent handoffs.

Rank 5Flag in-flight decisions when the ground shifts

From time reflection. When a project's circumstances change abruptly (stakes edited, owner changed, a dependency archived), flag every open receipt in it for review. Needs a registry of projects first.

Kill ifflagged receipts are rarely changed on review.

A herald has to come from the memory that holds the thing, at the moment it holds it. A herald that survives its write is a false receipt with a timestamp.

The essay tells the rest: how the session that wrote this broke rule I7 with a dry run that was not dry, and refused the false receipt it left behind.
