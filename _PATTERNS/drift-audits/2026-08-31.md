## DRIFT FOUND

### 1. Stale `vercel.json` `kelly-interview.arcs.care` rewrite — unresolved, now 6 weeks running

- Evidence: `vercel.json` `rewrites` array (lines 20-23), unchanged again this week:
  ```json
  {
    "source": "/",
    "has": [{ "type": "host", "value": "kelly-interview.arcs.care" }],
    "destination": "/kelly-interview.html"
  }
  ```
  `public/kelly-interview.html` still does not exist (confirmed this run — `ls`
  fails). The correct, authoritative handler remains `next.config.ts`'s
  `{ source: "/:path*", destination: "/warroom/kelly-interview", has: [{ type: "host", value: "kelly-interview.arcs.care" }] }`
  (admin-gated, confirmed working this run — see Check 3 below). First flagged
  2026-07-27, repeated 2026-08-03, 2026-08-10, 2026-08-17, 2026-08-24, and now
  again — **six consecutive weekly audits with no cleanup.**
- Why it matters: same as every prior report — split-brain routing risk for one
  of the hardened internal briefs. The static destination is dead today (the
  target file doesn't exist), but if Vercel's platform layer ever evaluates
  `vercel.json` rewrites ahead of `next.config.ts`, this stale entry could
  shadow the correct admin-gated route — or if a stray `kelly-interview.html`
  is ever reintroduced to `public/`, this rule would immediately serve it
  ungated, bypassing the exact protection the 2026-07-24 hardening built.
- One-line fix: delete the `kelly-interview.arcs.care` entry from
  `vercel.json`'s `rewrites` array. Recommended identically six times now —
  flagging directly to a human since the auditor does not fix drift itself.
