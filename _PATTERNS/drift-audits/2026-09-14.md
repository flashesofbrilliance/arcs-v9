### 2. `public/static-serve.py` — a local dev script, world-readable in production, with a hardcoded local path

- Evidence: `leak_check.sh`'s stray-source gate (also only visible via a
  standalone re-run, since the script stops at the first failure):
  ```
  ✘ STRAY SOURCE: 1 source/doc file(s) served world-readable in public/:
      public/static-serve.py
  ```
  Full file contents (17 lines) are a `http.server`-based static file server
  for local QA, including the line `os.chdir('/Users/zharris/arcs-v9/public')`
  — a hardcoded local filesystem path, the exact class of leak
  `scripts/leak_check.sh`'s own denylist (`/Users/[a-z]`) exists to catch on
  HTML surfaces, just not on `.py` files, which the internal-marker scan
  doesn't cover. Added 2026-09-11 in `268c14a` ("capture pre-handoff working
  state"), so it landed as an incidental part of a state-capture commit, not
  deliberately.
- Why it matters: anyone can currently fetch `<any-arcs.care-host>/static-serve.py`
  and see this file in the clear, including the developer's local username and
  directory layout — a minor but real local-machine leak class, and generally
  a `.py` file has no business being served from `public/`.
- One-line fix: `git rm public/static-serve.py` (or move it to `scripts/` if
  it's still wanted as a local QA helper — `launch.json` already references a
  static preview server per `147aaf0`, worth checking if that's the intended
  home).
