# JTBD graph pre-registration, amendment 8 (2026-10-20): MCP tools as a cached index (Sprint 6)

Amends ADR-089 and `_PATTERNS/2026-10-18-jtbd-graph-preregistration.md`. Backlog row
`jtbd-graph-s6-mcp-tools`. Design approved by Zach 2026-10-20: a small cached index plus retrieval of
only the slice a job needs; no full tool definitions are preloaded or cached. Written and committed
before any emitter, adapter or query code for Sprint 6, and before any count.

## What was seen first
1. Sessions see MCP tools only as deferred names (`mcp__<prefix>__<tool>`); a schema loads on demand
   through ToolSearch. The prefix is either a server's own name (`supabase`, `Figma`,
   `plugin_resend_resend`) or a claude.ai connector id (a UUID).
2. The MCP config files do not list tools: `~/.claude/mcp.json` names local servers only, there is no
   repo `.mcp.json` tool list, and claude.ai connectors and plugins are not in any local config file.
3. `session_connectors_status` (desktop app) returns each server's name, kind and, for a connector,
   its id. That is the only place the UUID prefix is tied to a human name.
4. Receipt `2026-10-20--receipt-append-only-applied--ZH` records `tool_id = tool:script:safe_merge.sh`,
   but its own `what_confirmed` says the work was done by `apply_migration`. That session's transcript
   shows the call was `mcp__supabase__apply_migration` (the project-kind server named `supabase`).

## Rule (a): source of truth
**A committed snapshot, `runtime/specs/mcp-tool-index.json`, regenerated by
`scripts/mcp_tool_index_emit.py` from a capture taken inside a session.** A capture is one JSON file
holding the session's deferred MCP tool names plus the `session_connectors_status` server rows, and a
`captured_at` date. The config files were rejected as the source because they hold no tool names and
miss every connector and plugin (seen-first 2).
- Fields per tool: `kind` ("mcp"), `name` (`<server>.<tool>`, the id key), `server`, `tool`, `fn` (the
  deferred name, so a session can load exactly it), `purpose` (one line), `class` (read or write).
  Never an input schema, parameter list or description longer than one line (no field outside this list).
- Purpose: the capture's own one-liner when it supplies one, else the tool name in words, marked
  `(from name)`. Never invented beyond the name.
- Staleness: the snapshot is STALE when `captured_at` is more than 30 days before today, or when a
  newer capture lists a server or tool the snapshot lacks. `mcp_tool_index_emit.py --check` exits 1 on
  STALE; the adapter `--check` prints a STALE warning and does not fail the pre-commit gate (a
  connector change on Zach's account must not block unrelated commits). Re-capture is the fix.
- Prefixes not tied to a listed server are dropped and counted in the emitter output, never guessed.

## Rule (b): id scheme `tool:mcp:<server>.<tool>` (new namespace, minor version 1.1.0)
- `<server>` is a stable label: the server's own name from `session_connectors_status`, last `:`
  segment for a plugin (`plugin:resend:resend` -> `resend`), lowercased, every run of characters
  outside `[a-z0-9]` becomes `-`. Never the connector UUID.
- Collision: when two servers give the same label, the one whose deferred prefix is its own name
  keeps the plain label, and a claude.ai connector gets `-claudeai` (`supabase` and
  `supabase-claudeai`; `figma` and `figma-claudeai`). Any remaining collision is SOURCE-DUP: the
  emitter refuses.
- `<tool>` is the tool name verbatim. Key pattern `^tool:mcp:[a-z0-9-]+\.[A-Za-z0-9_-]+$`.
- A connector rename is a new id plus a `replaces` edge (ADR-089 rename rule). The write-lock on
  existing namespaces is untouched.

## Rule (c): read or write class
Split the tool name on `_` and `-`; drop leading tokens that equal the server label's tokens
(`notion-search` -> `search`). **Read** only when the first remaining token is one of get, list,
search, query, read, view, fetch, count, inspect, AND no token anywhere is a write verb (create,
update, delete, remove, send, set, add, apply, deploy, execute, run, merge, reset, rebase, pause,
unpause, restore, publish, post, write, upsert, patch, put, cancel, trash, untrash, forward, reply,
share, unshare, move, rename, import, upload, buy, enable, disable, sign, revoke, rotate, kill, stop,
start, invalidate, approve, edit, label, unlabel, mark, unmark, generate, copy, duplicate, record,
complete, issue, assign, connect, transfer, verify, confirm, save, submit, respond, give, provision,
activate, extend, stage, replace, retry, rerequest, request, accept, authorize, change, resolve,
spawn, convert, remix, mint, initiate, test, or, and). **Write** is everything else, including any
name the rule cannot parse. Unsure means write.

## Rule (d): edges from evidence only
- `serves` edge `tool:mcp:X -> job:backlog:Y` only from a decision receipt whose `tool_id` is
  `tool:mcp:X` and whose `job_id` is `job:backlog:Y`. The emitter's `--receipts` mode writes those
  rows (receipt_id, job_id, tool_id, event_at; nothing else) from the gitignored receipt export to the
  committed `runtime/specs/mcp-tool-receipts.jsonl`. Edge evidence: that file's line plus
  `receipt:<id>`; `receipt:` evidence resolves offline only when the id is on a line of that file.
- No edge from a tool name, a purpose line or any text match. A tool with no receipt has no edge.
- `tool:mcp:*` atoms are an index, not owned tools: they are exempt from ORPHAN-TOOL. They still count
  for ORPHAN-JOB (a job served by an MCP tool through a receipt edge is not an orphan).

## Rule (e): retrieval
- MCP tools never enter the BM25 ranking, so s4's repo ranking is byte-identical. `jtbd(job)` adds a
  field `mcp`: at most 5 MCP tools with a live `serves` edge to the matched jobs, each with its class.
- Every write-class tool in an answer carries `"flag": "write: confirm before use"`; the rendered text
  prints the same words on its line.
- One hint line: `load: ToolSearch select:<fn>,<fn>` naming only those tools.
- The 1,000-token budget holds with the `mcp` field included; it is trimmed before anything else.
