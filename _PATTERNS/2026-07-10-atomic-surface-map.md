## 2. The Manifest Law (parameterization contract)

Every reusable artifact — at every layer — declares a manifest. Zod is already a dependency; the schema is code, not prose:

```ts
// runtime/specs/artifact-manifest.ts (to create)
ArtifactManifest = {
  name: string,            // kebab-case, unique in registry
  layer: 'token'|'atom'|'molecule'|'organism'|'template'|'page'|'service',
  params: ZodSchema,       // the ONLY inputs; no hidden globals
  tokens: string,          // token-set version it compiles against
  targets: ('react'|'static-html'|'og-image'|'markdown'|'email'|'print')[],
  deps: string[],          // manifest names — the runtime dependency map is derived, never drawn
  events: string[],        // telemetry it emits (track()/OTel span names)
  provenance: { commit: string, nci: string },  // traceability stamp
}
```

Registry: `runtime/specs/artifact-registry.json` — generated by walking manifests, consumed by the cross-compiler, the Drift Sentry, and the dependency graph. `src/document/registry.ts` (DOC_TYPES × DOC_PATTERNS) is the proof this pattern already works; the law generalizes it to all four systems.

     │                                      │

     │

Law: an artifact may only import DOWN the chain (page→template→organism→…→token) and may only emit data UP through Receipt-shaped JSON. Cycles are drift; the sentry flags them.

## 6. Traceability · transparency · observability

- **Receipts ARE traces.** Mapping (no new deps needed to adopt the semantics): `receiptId` = trace_id · L0–L5 = spans · Y-gate fields = span attributes · `parentId` lineage = trace links · SageTrace = existing span table. The compass route already records latency (t0) — formalize span boundaries in the JSON it stores.
- **OTel proper:** `@vercel/otel` is a **new dependency → requires Zach's explicit approval** (repo law). Until then: `track()` events (8 live) + SageTrace + provenance stamps are the observability layer. No fake telemetry claims.
- **Transparency:** every rendered artifact carries its provenance line (commit, NCI, template version, params hash) — the meta-audit artifact's footer is the pattern; make it a token-level atom (`ProvenanceFooter`).
- **Cross-compile each turn:** the Drift Sentry (08:00 routine) + CI check: when `tokens.json` or any manifest changes → recompile targets → stamp provenance → inchworm entry. Stale compiled output = drift, flagged not silently fixed.

## 7. Self-sovereignty ladder (local-first, network-to-enrich)

| Rung | State | What it means |
|---|---|---|
| L1 ✅ | anonymous localStorage session + claim-on-login (ADR-016) | you can use the compass with no account |
| L2 🟡 | export everywhere — every receipt/brief/report downloadable as .md/.json (partial: recoil JSON exists, meta-audit artifact exports; receipts don't yet) | your record leaves with you, always |
| L3 🔴 | local vault — receipts written to IndexedDB (client) / SQLite (dev parity exists via better-sqlite3) first, synced to Postgres opportunistically | **reading your atlas never requires the network** |
| L4 🔴 | GIGI fiber-bundle substrate (canon-planned seam at compass route) | full local-first graph store |

Enrichment (Claude calls, sync, share links) is what the internet is *for*; the record itself is yours offline. L2 is cheap and next; L3 needs an ADR (offline-write + sync conflict policy); L4 stays gated behind GIGI.
