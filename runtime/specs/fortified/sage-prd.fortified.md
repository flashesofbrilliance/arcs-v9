# SAGE: fortified requirements (v2.0.0-fortified)

## Cold read

- **Why this spec exists:** to say what SAGE is and what it should become, so a builder knows what to wire.
- **What it is now:** an evidence-tagged replacement for the April 2026 SAGE PRD/TRD/DRD, written mostly in Perplexity before ARCS had evidence gating.
- **Why now:** the pressure test found the spec describes a different SAGE from the one in the repo. Of 37 ledgered claims, 3 verified, 13 false, 7 contradicted inside the spec itself.
- **How to use it:** before building, read Verdict and Gaps, and check that `svc-sage-should-it-exist-decision` has left HELD. During, build only from What holds. After, any hypothesis you test moves to What holds or Corrected, with its evidence.
- **How to read this page:** every statement carries a file:line, a command or a URL. Anything without one sits under Hypotheses. Paths are relative to the arcs-v9 repo root.

## Verdict

No one can build the product this spec describes from it today. Its central object does not exist: the repo's SAGE is a Discernment operator ("is this signal or noise?") that runs first in the operator pipeline as a fail-open, advisory pre-screen whose output users never see. The spec instead sells an L4/L5 "truth-extraction engine," a standalone `/api/sage/*` product, and a new stack (Next 15, Tailwind, Supabase Auth, Railway, OpenAI embeddings, new receipt tables) that contradicts the repo on every line. Whether SAGE should exist as a service at all is a HELD decision with no data behind it yet. What a builder can use: the NOTOMATION stance (SAGE never decides), the signal-versus-noise purpose, and the idea of a tamper-evident receipt, which the repo already carries in other models. Everything else is a hypothesis or needs a ruling from Zach.

## Gaps and open questions

1. **Identity (Zach decides).** Is SAGE the Discernment pre-screen that exists, or a new L4/L5 synthesis layer under a different name? The spec's purpose overlaps (signal from noise) but its position and mechanism do not.
2. **Numbering (Zach decides).** SAGE has no entry in `operators/docs/PERIODIC-TABLE.md` (grep: 0 hits). Row `op25-sage-naming-ruling` is OPEN: another doc calls Op 25 "Sage," but the table names Op 25 ShavasanaSpace. This page binds SAGE to no number (AGENTS.md gotcha 16).
3. **Existence (Zach decides, gated).** `svc-sage-should-it-exist-decision` is HELD until `accountant-calibration-curve` is DONE. If NO, remove `/svc/sage`. If YES, the fork is TypeScript inline versus keeping Python for op20.
4. **No efficacy data.** The study script exists but has nothing to read until external outcomes arrive.
5. **Broken cite.** `route.ts:276` and the backlog row point at `scripts/sage_efficacy.py`, which does not exist; the file is `.mjs`.
6. **Repo overclaim.** "signed CoherenceReceipt" (`arcs_operators_sage.py:16`) has no signing code behind it.
7. **GDPR versus sealed receipts.** If personal data lands on an immutable record, erasure needs a design such as keeping it off the sealed record or deleting a key. Not checked against GDPR Article 17 text.
8. **New vendors.** OpenAI embeddings and Perplexity grounding would be new dependencies and new processors. Both need Zach's yes and a trust page update.

## Kintsugi seam

- **It renamed and moved the thing it described.** The spec gave SAGE a new acronym and put it last in the stack as the product core. The repo SAGE is first, advisory and invisible, and may yet be deleted.
- **It borrowed repo words with new meanings.** NCI, the L0 to L4 labels, the kinematic ladder and the Drift Sentinel all exist in canon with other definitions. A reader who trusts the familiar word gets the wrong quantity.
- **It graded itself.** A high self-score, absolute accuracy and latency claims, and "cryptographic-grade" language read as evidence but rest on no test, benchmark or key. The repo docstring shows the same habit, so the fix is a gate, not one edit.
